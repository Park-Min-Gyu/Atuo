# YL_AUTO v24 수정 내역 (2026-11-27, 헥사 메시 YL_HEX_V6 추가)

## 추가한 것
연구실 **YL_HEX_V6_PURE_2mm.tcl** (HyperMesh 2019, SolidMap 순수 헥사)을 메시 엔진으로 고를 수 있게 했다.
YL_AUTO(전체 파이프라인)와 YL_MESH_SETS(메시 + INNER/OUTER 묶음) 둘 다.

```
config 의 hypermesh.engine (YL_MESH_SETS 는 engine)
  "v10" (기본) : YL_V10 Tetra -> gmsh -> TetWild
  "hex"        : YL_HEX_V6 순수 헥사(C3D8H) -> 안 되면 위 Tetra 순서로 자동 전환 (hex_fallback_tet: true)
```

## 원본 스크립트
- `hypermesh/YL_HEX/YL_HEX_V6_PURE_2mm.tcl` : 받은 원본 그대로. HyperMesh 에서 File > Run 으로 단독 실행(설정 창)도 그대로 된다.
- 원본은 마지막 줄에서 설정 창을 띄우므로, `core/yl_hex.py` 가 실행할 때마다 그 한 줄만 뺀 복사본을 만들어
  hmbatch 로 '헥사 + 3D' 모드(`ylh6_run_3d`)를 바로 부른다.
  설정 : select_mode all, quad_fallback 0 (대화창 없음), save_hm 1, export_inp 1, 요소 C3D8H.
- 원본 스크립트의 요소크기는 **2.0 mm 고정**이다 (config 의 elem_size 는 Tetra 로 갈 때만 적용).

## 헥사 합격 조건 (아니면 Tetra 로)
- Abaqus INP 가 나왔고 (원본은 음의 Jacobian 요소가 있으면 INP 를 안 씀)
- 헥사 1 개 이상, 웨지(penta) 0 개, 매핑 안 된 솔리드 0 개
- Tetra 로 넘어간 모델은 `hm_status.txt` 에 `HEX_FAILED` 를 남겨서, 다음 실행 때 헥사를 매번 다시 시도하지 않는다.

## 파이프라인이 헥사(C3D8H)를 처리하도록 고친 것
| 부분 | 예전 | 지금 |
|---|---|---|
| 원점/INNER/OUTER 판별의 그림자 계산 | 사각형 면의 앞 3 절점(절반)만 사용 | 사각형을 삼각형 2 개로 나눠 전부 사용 |

| 부피 (형상 특징값) | 헥사는 NaN | 계산 |

## 검증
- 구조 격자로 만든 시험 헥사 부싱 2 개 (원통 / 바깥 사각형 + 원형 보어) 로 build -> (가짜) 해석 -> 리포트 통과
  - 부피 80,323 / 95,603 mm³ (이론 80,425 / 95,594), INNER·OUTER 면적 이론값과 일치, `type=C3D8H` 출력
- YL_HEX 실행 래퍼 : 단순한 가짜 HyperMesh 로 원본 스크립트를 실제로 불러 '솔리드 없음' 경로까지 끝까지 실행 (대화창 없음)
- 가짜 hmbatch 로 세 경우 : 헥사 성공 / 헥사 실패 -> Tetra 전환 / 다음 실행 때 재사용
- 기존 Tetra 시험 모델 결과 변화 없음

## 알아둘 점
- **SolidMap 은 매핑 가능한 솔리드에서만 헥사를 만든다.** 공극·필렛·스토퍼가 많은 부싱 솔리드는 통째로는
  매핑이 안 되는 경우가 많다 (원본 스크립트도 'Geom -> Solid Edit -> Trim 으로 블록을 나누라'고 안내한다).
  이 경우 자동으로 Tetra 로 넘어간다. 자동으로 솔리드를 나누는 기능은 없다.
- 실제 HyperMesh 에서 이 래퍼로 헥사가 나오는지는 아직 확인하지 못했다. 첫 실행 때
  `mesh/_logs/hex_status.txt` (N_HEX, N_UNMAP) 와 `C:/Temp/YL_HEX_V6_logs/YL_HEX_V6_report.txt` 를 확인할 것.
