# YL_AUTO v9 수정 내역 (2026-11-12, bushing.stp "tetmesh 0개" 오류 대응)

## 결론 : HyperMesh 고장이 아니라 자동화 코드(YL_V5_batch.tcl) 버그 + 형상(0.2 mm 글자) 문제
로그에서 확인된 사실
- `CASE_A=0, CASE_B=4914` : 면 4914개 전부 Case B. 부싱 끝면/원통면까지 "좁은 면"으로 분류됨
- `defeature: 작은 면 0 개` : v8 에서 넣은 "글자 자동 무시"가 한 개도 못 찾음
- `F3 Node Merges 167737`, `Aspect>5 Tria 7829` : 글자를 2 mm 요소로 그대로 메시해서 표면이 망가짐
- 그 표면으로 tetmesh -> 글자 안쪽 작은 주머니만 3개 메시, 본체는 0개

위 두 줄(Case A 0개, 작은 면 0개)의 공통 원인은 **면적 함수 호출 문법 오류**다.
`sc_get_surf_area` 가 `hm_getareaofsurface $sid` (인자 1개)로 불렀는데 HM2019 문법은
`hm_getareaofsurface surfs $sid` 이다. 오류가 `catch` 에 묻혀 면적이 항상 0 으로 나왔다.
-> 폭 = 면적/길이 = 0 -> 모든 면이 Case B, defeature 는 `면적<=0 이면 건너뜀` 이라 0개.

`topo edge 12389 is not terminated on vertex` 는 4번째 시도(solid 형상 직접 메시)에서 HyperMesh 가
낸 메시지로, 그 CAD 모서리의 위상이 깨져 있다는 뜻이다(형상 쪽 문제). 1~3번 시도 실패의 원인은 아니다.

## 수정
### hypermesh/YL_V5_batch.tcl
| # | 내용 |
|---|---|
| 1 | `sc_get_surf_area` : `hm_getareaofsurface surfs id` -> `hm_getareaofsurface id` -> `hm_getvalue surfs dataname=area` 순으로 되는 방식을 찾아 사용. 어떤 방식인지 hm_log.txt 에 `면적 함수 확인` 으로 기록, hm_status.txt 에 `AREA_API`, `AREA_FAIL` |
| 2 | defeature : 면적을 못 구한 면은 bounding box 크기로 판정(예비). 로그에 `면 N 개 중 작은 면 M 개 ... 남은 면 K 개` |
| 3 | `yl_shell_check` (신규) : tetmesh 직전에 표면 Tria 를 직접 검사. free edge(구멍) / T edge(겹침) / 중복 / 면적0 Tria 개수를 `check:` 줄로 기록하고 중복·면적0 Tria 는 삭제 |
| 4 | fallback 을 1회 -> 최대 3회 : ①그대로 ②작은 면 기준 2배(defeature x2) ③defeature x2 + 표면 요소 0.7배 |
| 5 | `*tetmesh` 두 번째 마크를 0 -> 2(빈 마크)로 변경 (GUI 가 기록하는 형식과 동일) |
| 6 | V4 단계가 free edge 때문에 tetmesh 를 건너뛸 때 로그 없이 넘어가던 것 -> 이유 기록 |
| 7 | fallback 후 `BAD_TRIA` 를 다시 계산 (예전에는 V4 단계 값이 그대로 남았음) |

### Python
- `core/gmsh_mesher.py` (신규), `core/runners.py: run_gmsh` : **예비 메셔**. HyperMesh 가 끝까지 실패하면
  gmsh 로 Tet 메시를 만들어 build 단계로 넘긴다 (`pip install gmsh` 필요, 없으면 안내만 하고 건너뜀).
  로그에 "gmsh 로 만들었습니다" 라고 표시되고 `hm_status.txt` 에 `ALGO=GMSH_FALLBACK`.
- `config_abaqus.json` : `gmsh_fallback { enabled, size_min_ratio, timeout_min }`
- `check_env.py` : gmsh 설치 여부 표시

## 검증 범위 (중요)
- 이 수정은 HyperMesh 가 없는 환경에서 작성했다. Tcl 은 HyperMesh 명령을 흉내 낸 모의 환경에서
  문법과 흐름(defeature, 표면 검사, fallback 3회, 상태 파일)만 확인했다. **실제 HyperMesh 2019 에서는 아직 안 돌려 봤다.**
- gmsh 예비 메셔와 Python 은 0.2 mm 양각이 있는 시험용 부싱 STEP 으로 mesh -> build 까지 실제로 돌려 확인했다.

## 다시 실행
```
pip install gmsh
run_all.bat --only bushing --force
```

## 그래도 실패하면 hm_log.txt 에서 볼 줄
1. `면적 함수 확인 : '...' 방식 사용` 이 있는가 -> 없으면 면적 함수가 여전히 안 되는 것
2. `defeature: 면 4914 개 중 작은 면 N 개` -> N 이 수천 개여야 정상
3. `Case A` 개수가 0 이 아닌가
4. `tetmesh 입력 표면 check: ... free_edges=? T_edges=?` -> 둘 다 0 이어야 tetmesh 가 된다
