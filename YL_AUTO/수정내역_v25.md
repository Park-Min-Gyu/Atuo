# YL_AUTO v25 수정 내역 (2026-11-27, 헥사 전용)

## 요청
"이 자동화는 무조건 헥사로 돌린다."
v24 에 있던 '헥사가 안 되면 Tetra 로 넘어가기'(`hex_fallback_tet`)는 요청받은 기능이 아니라 안전장치로 임의로 넣은 것이었다.
v25 에서 **완전히 삭제**했다. 이제 메시는 YL_HEX_V6 순수 헥사(C3D8H)만 쓴다.

## 바뀐 것
| 항목 | v24 | v25 |
|---|---|---|
| 기본 메시 엔진 | `v10` (Tetra) | **`hex`** (YL_HEX_V6 SolidMap 순수 헥사, C3D8H, 2.0 mm). config 에 `engine` 줄이 없어도 `hex` |
| 헥사가 안 될 때 | YL_V10 → gmsh → TetWild Tetra 로 자동 전환 | **그 모델만 메시 실패로 끝남** (다른 모델은 계속 진행). Tetra 메셔는 실행도 안 함 |
| `hex_fallback_tet` 설정 | 있음 (true) | 삭제 (코드도 더 이상 안 읽음) |
| `mesh.mesher: "gmsh"` (gmsh 우선) | 헥사보다 먼저 gmsh Tetra | 헥사 모드에서는 무시 |
| 이전 메시 재사용 | STATUS=OK 면 Tetra 메시도 재사용 | **헥사(YL_HEX) 메시만** 재사용. 예전 Tetra 메시가 있으면 헥사로 다시 메시 |
| `models` 폴더의 .inp | Tetra .inp 도 해석 | **헥사 .inp 만**. Tetra .inp 는 build 에서 이유를 출력하고 그 모델만 중단 |
| 헥사 메시 재사용 판정 | `fixed_size` 비교 때문에 매번 다시 메시될 수 있었음 | 헥사는 비교 안 함 (원본이 2.0 mm 고정) |
| 메시 실패 안내 문구 | "GUI 에서 직접 메시한 .inp 를 넣어라" | "매핑 안 되는 솔리드는 HyperMesh 에서 블록으로 나누거나, 헥사 .inp 를 넣어라" |
| `check_env.py` | 헥사 항목 없음 | 헥사 원본 스크립트 + 배치용 복사본 확인, `메시 엔진: 헥사 전용` 표시 |
| YL_MESH_SETS | 헥사 실패 → Tetra | 헥사 전용 (실패하면 그 모델 실패, Tetra .inp 거부) |
| README / 사용설명서 | Tetra(YL_V5, C3D10H) 기준 설명 | 헥사(YL_HEX_V6, C3D8H) 기준으로 고침 |

## 헥사 전용이라 생기는 일 (꼭 읽을 것)
- **SolidMap 은 '매핑 가능한' 솔리드에서만 헥사를 만든다.** 공극·필렛·스토퍼가 많은 부싱 솔리드를 통째로 넣으면
  `N_UNMAP` 이 1 이상이 되고 그 모델은 실패한다.
  → HyperMesh 에서 Geom → Solid Edit → Trim 으로 매핑 가능한 블록으로 나눠 저장한 뒤 다시 넣는다 (원본 스크립트 안내와 같음).
  솔리드를 자동으로 나누는 기능은 없다.
- HyperMesh 가 솔리드를 0 개로 읽는 CAD (예전 Part2 / Part5 / Part6 처럼 면이 깨진 STEP) 는 헥사도 0 개 → 실패한다.
  예전에는 TetWild(Tetra)가 대신 살렸지만, 이제는 CAD 를 고쳐야 한다.
- `models` 폴더에 넣어 둔 Tetra .inp (예전 결과 등) 는 해석하지 않는다. 빼거나 헥사 .inp 로 바꿀 것.
- 요소크기는 원본 스크립트대로 **2.0 mm 고정**. `mesh.elem_sizes` 가 2.0 이 아니면 로그에 알리고 2.0 mm 로 만든다.
- 끝난 해석(ODB) 은 v22 규칙 그대로 입력이 같으면 다시 안 돌린다.
  단, **예전에 Tetra 로 끝난 모델은 메시가 헥사로 바뀌므로 한 번 다시 해석되고, 같은 폴더의 예전 ODB 를 덮어쓴다.**
  예전 Tetra 결과를 남기고 싶으면 실행 전에 `auto_out` 폴더를 다른 이름으로 복사해 둘 것.
- 헥사가 실패한 모델은 다음 실행 때 다시 헥사를 시도한다 (CAD 를 고쳐 넣으면 자동으로 반영).

## 확인 방법
- 실행 로그 `mesh OK  hex=개수` → 헥사 성공
- 실패하면
  `헥사 메시 실패 -> YL_HEX : 헥사 0개 (...); 매핑 안 된 솔리드 1/1개 (형상을 매핑 가능한 블록으로 나눠야 함)`
  `메시 실패 -> 이 모델은 해석(ODB) 단계로 가지 않습니다. 헥사 전용 모드: ...`
- `auto_out/<모델>_Ep2p0/mesh/_logs/hex_status.txt` : `N_HEX`, `N_PENTA`, `N_SOLIDS`, `N_UNMAP`
- `C:/Temp/YL_HEX_V6_logs/YL_HEX_V6_report.txt` : 원본 스크립트의 리포트
- `python check_env.py config_abaqus.json` → `[OK] YL_HEX 헥사 엔진`, `메시 엔진: 헥사 전용 (C3D8H, 2.0 mm 고정, Tetra 로 넘어가지 않음)`

## Tetra 를 쓰는 경우 (직접 바꿀 때만)
- `config_abaqus.json` 의 `"hypermesh": {"engine": "v10"}` 으로 **직접 적었을 때만** Tetra. 자동으로 바뀌는 일은 없다.
- `config_abaqus_smoketest.json` 은 Abaqus 점검용 Tetra 시험 모델(.inp)을 쓰므로 `v10` 그대로 둔다 (실제 해석과 무관).

## 검증 (가짜 HyperMesh / 가짜 Abaqus)
- 헥사 성공 → `mesh OK hex=11520` → `build OK: C3D8H` (INNER 1512, OUTER 1512) → 통합 Job 1개 → 15/15
- 두 번째 실행 (`--force` 없음) : HyperMesh 안 부르고 헥사 메시 재사용, 해석도 "이전 해석 결과 재사용 (15/15)"
- 헥사 실패 → YL_V10 / V9 / V8 / gmsh / TetWild 아무것도 실행 안 됨, 그 모델만 실패 + 헥사 안내 문구
- config 에 `engine` 줄이 없어도 헥사로 실행
- `mesh.mesher: "gmsh"` 여도 헥사만 실행
- Tetra .inp 모델 → build 에서 거부 (그 모델만, 나머지는 계속)
- `engine: "v10"` 으로 직접 바꾸면 예전 Tetra 결과 그대로 (회귀 시험 2 모델 build OK, smoketest mesh+build OK)
- YL_MESH_SETS : 헥사 성공 / 헥사 실패 시 Tetra 안 감 / Tetra .inp 거부
- check_env : 정상 스크립트 OK, 엉뚱한 파일이면 NG + 이유
- 실제 HyperMesh 2019 에서 이 래퍼로 헥사가 나오는지는 아직 확인 못 함 → 첫 실행 때 위 `hex_status.txt` 를 볼 것
