# YL_AUTO v8 수정 내역 (2026-11-12, bushing.stp 오류 대응)

## 증상
- `ValueError: 반경 방향 경계면을 찾지 못했습니다` (run_pipeline.py build 단계)
- 실제 원인: HyperMesh 가 만든 `bushing_hm.inp` 에 **Tetra 가 3개뿐** (x=19.0~19.2 mm, 끝면 양각 글자 0.2 mm 안쪽).
  그런데 hm_status.txt 는 `STATUS=OK` 로 기록되어 Python 이 그대로 build 로 넘어갔다.

## 원인
| # | 위치 | 원인 |
|---|---|---|
| 1 | YL_V5_batch.tcl `*tetmesh` | HM2019 문법은 `*createstringarray N "tet: ..." ...` 다음에 `*tetmesh ... 1 N` 인데, 마지막 인자에 `"1 1.2 2 0 0.8 0 0"` 문자열을 넣었다. command.tcl 에 `*tetmesh elements 1 1 elements 2 -1 1 0` (파라미터 문자열 0개)으로 기록되었고 Tetra 3개만 생성됨. V4 단계도 같은 이유로 0개 -> fallback 도 3개 |
| 2 | YL_V5_batch.tcl `*orderchange` | HM2019 에 없는 명령(catch 에 묻힘). 그래서 항상 C3D4 로 출력됨. `*orderchangetosecond` 로 교체 |
| 3 | 형상 | 끝면 0.2 mm 양각 글자(면 4914개 대부분)를 2 mm 요소로 메시 -> 찌그러진 Tria 7829개, F3 병합 16만 회. tetmesh 실패 위험이 큼 |
| 4 | 상태 판정 | Tcl/Python 모두 `n_tet > 0` 이면 OK. 3개짜리도 통과. 또 다음 실행 때 이 불량 메시를 캐시로 재사용함 |

## 수정
### hypermesh/YL_V5_batch.tcl
- `yl_tetmesh_robust` : 올바른 문법으로 4가지 방법을 차례로 시도
  1. shell_fixed (표면 Tria 고정)  2. shell_float (Tria 수정 허용)  3. 파라미터 최소  4. solid 형상에서 직접(volume tetra)
  각 시도의 결과를 hm_log.txt 에 `tetmesh <방법> input=... n_tet=...` 로 기록
- Tetra 합격 기준: `n_tet >= max(50, 0.25 × 표면 Tria 수)`. 미달이면 V4 -> fallback, 그래도 미달이면 STATUS=FAIL
- `yl_suppress_small_features` : 폭 < 0.25×요소크기 이고 가장 긴 모서리 < 5×요소크기 인 작은 면(글자 벽면/윗면)의
  모서리를 `*edgesmarksuppress` 로 suppress -> 메셔가 글자를 무시하고 끝면을 평평하게 메시
- `*orderchangetosecond` 로 C3D10 생성 (실패해도 Python 이 C3D10 으로 변환)
- hm_status.txt 에 `N_TET_MIN`, `DEFEATURED` 추가

### Python
- `core/runners.py` : `tet_count_ok()` 추가. STATUS=OK 라도 Tetra 수 부족이면 FAIL. 1차에서 이미 fallback 까지 했으면 같은 재시도 생략
- `run_pipeline.py` : 이전 메시 재사용 전에 Tetra 수 검사(불량이면 HyperMesh 재실행). build 시작 시 요소 수 검사, 떨어진 요소 덩어리 제거
- `core/inp_mesh.py` : `check_mesh_sane()`, `keep_largest_component()` 추가, 경계면 오류 메시지에 원인 추정 정보 추가
- `config_abaqus.json` : `hypermesh.defeature / small_w_ratio / small_maxlen_ratio / tet_min_ratio`, `mesh.min_elems`

## 다시 실행
```
python run_pipeline.py config_abaqus.json --only bushing --force
```
(`--force` 없이 실행해도 이전 3-tet 메시는 자동으로 버리고 다시 메시합니다.)
