# YL_AUTO v23 수정 내역 (2026-11-25, "중간절점이 모서리 중점과 맞지 않습니다" 오류)

## 증상
새 모델 5개 중 2개(1660559-00 MID_BUSHING_POR, MID_DRT)가 메시는 끝났는데 build 단계에서 멈춤
```
ValueError: 요소 25337: 중간절점이 모서리 중점과 맞지 않습니다(곡면 투영이 매우 큼).
```

## 원인
- HyperMesh(YL_V10)는 2차 요소(C3D10H)로 바꿀 때 **중간절점을 CAD 곡면 위로 옮긴다** (`*orderchangetosecond 1 1`).
- 작은 필렛처럼 많이 휜 곳에서는 중간절점이 모서리 중점에서 크게 벗어난다.
- 예전 코드는 중간절점마다 '가장 가까운 모서리 중점'을 찾아 순서를 추정했는데, 휜 정도가 크면 판단이 겹쳐서 **오류로 멈췄다**.
- 메시나 형상의 문제가 아니라 **파이프라인 검사 코드의 문제**였다.

## 수정 (`core/inp_mesh.py` 의 `fix_tet10_midside_order`)
1. 순서 : 파일 전체에서 가장 많이 쓰인 순서(HyperMesh 는 Abaqus 순서)를 판단이 안 되는 요소에도 적용 -> 멈추지 않음
2. 너무 휜 중간절점 : 모서리 길이의 20 % 넘게 벗어난 것은 모서리 중점으로 옮김
   (그대로 두면 Abaqus 에서 요소가 찌그러지거나 뒤집혀 발산 원인이 됨. 곡면 형상 차이는 해당 모서리에서만 0.1 mm 수준)
3. 로그에 몇 개를 재배열/이동했는지 남김

## 검증
- MID_DRT STEP 을 곡면을 따르는 2차 요소로 메시해서 **같은 오류를 재현** (요소 901) -> 수정 후 통과
  - 순서 판단이 안 된 요소 212개 처리, 휜 중간절점 515개 중점으로 이동, 모든 요소 체적 > 0
  - build 통과 : 원점 이동 (-0.015, 0, 0.116) mm, INNER 9,274 / OUTER 7,083 노드, 반경 방향 스웨징
- 일부러 중간절점 순서를 다른 규칙으로 섞은 메시도 100 % 원래 순서로 복원
- 기존 시험 모델 결과 변화 없음
- MID_BUSHING_POR 는 HyperMesh 메시 파일이 없어 같은 메시로는 확인 못 했지만, 오류가 난 코드가 같아서 같이 해결될 것으로 본다.
- `YL_MESH_SETS/core/inp_mesh.py` 에도 같은 수정 반영.
