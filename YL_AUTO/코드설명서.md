# YL_AUTO 코드 설명서 (학생용)

부싱 CAD 와 고무 물성만 넣으면 HyperMesh 메시 → Abaqus INP → Job 실행 → ODB → 하중-변위/강성 데이터까지 자동으로 만드는 코드입니다.
사용법(설치, 실행 명령)은 `사용설명서.md` 에 있고, 이 문서는 "코드가 안에서 무엇을 하는지"를 설명합니다. 코드를 고치거나 결과가 이상할 때 어디를 봐야 하는지 알 수 있도록 쓰는 게 목적입니다.

---

## 1. 전체 흐름

```
 models/부싱.stp  +  config_abaqus.json (물성, 스웨징, 하중 조건)
        │
        ▼
 [1] mesh     HyperMesh 2019 배치(hmbatch) + YL_V5_batch.tcl
              → auto_out/<모델>_Ep2p0/mesh/<모델>_hm.inp      (Tet10 메시)
        │
        ▼
 [2] build    Python(numpy)으로 메시 검사·보정, 축을 +Y 로 회전,
              INNER/OUTER 노드 자동 선택, LOAD_RP(0,0,0) 생성
              → run/<tag>_mesh.inp (메시 전용) + Job INP 15개
        │
        ▼
 [3] run      abaqus job=... interactive      → run/<job>.odb
        │
        ▼
 [4] extract  abaqus python extract_odb.py     → run/<job>_RP.csv
        │
        ▼
 [5] report   강성 계산 + 자동 QC
              → dataset/summary.csv, curves.csv, qc_report.md, 그래프
```

- 단계는 `run_pipeline.py` 의 `STAGES = ["mesh", "build", "run", "extract", "report"]` 순서입니다.
- `--stage mesh,build` 처럼 일부만 돌릴 수 있습니다. 이미 끝난 단계는 건너뛰고, 다시 하려면 `--force` 를 붙입니다.
- 모델 1개당 Job 수 = 스웨징 5개(0, 1, 2, −1, −2 mm) × 하중 방향 3개(X, Y, Z) = 15개입니다.

## 3. 메인 프로그램 따라가기 (`run_pipeline.py` 의 `main()`)

코드를 처음 볼 때는 `main()` 만 위에서 아래로 읽으면 전체가 보입니다.

1. **설정 읽기** `load_config()` : json 을 읽고, 상대경로의 기준(`_base`)을 config 파일이 있는 폴더로 잡습니다. 그래서 `C:\YL_AUTO` 를 다른 위치로 옮겨도 동작합니다.
2. **모델 찾기** `check_models()` → `model_list()` : `models_glob`(기본 `models/*`)에 맞는 파일 중 CAD 확장자(.stp .step .igs .x_t .catpart .hm 등)나 .inp 만 모읍니다. 0개면 다른 폴더에 CAD 가 있는지 찾아 알려주고 멈춥니다. 모델 이름에 쓸 수 없는 문자는 `safe_name()` 이 `_` 로 바꿉니다.
3. **프로그램 경로** `resolve_programs()` : `findexe.py` 로 hmbatch.exe, abaqus.bat 을 찾습니다. 찾는 순서는 config 에 적은 경로 → 시작 메뉴 바로가기(.lnk) → 기본 설치 위치 → PATH 입니다.
4. **물성 준비** : `ogden.resolve_material()` 로 Ogden 계수를 확정합니다. 시험데이터 피팅 결과는 `material_cache/` 에 저장해 두고, 데이터가 바뀌지 않으면 다시 피팅하지 않습니다(sha1 해시로 비교).
5. **모델 × 메시 크기 반복** : `stage_mesh()` → `stage_build()`. 한 모델에서 에러가 나도 `error.txt` 를 남기고 다음 모델로 넘어갑니다.
6. **해석 + 추출** : `stage_run_one()` 을 Job 마다 부릅니다. `abaqus.max_parallel` 만큼 동시에 돌립니다(기본 1개씩).
7. **리포트** : `stage_report()`.

로그는 화면과 `auto_out/pipeline_log.txt` 에 같이 남습니다.

## 4. [1] mesh 단계 : HyperMesh 자동 메시

관련 코드: `stage_mesh()`, `runners.run_hypermesh()`, `hypermesh/YL_V5_batch.tcl`

### Python 쪽이 하는 일
1. 입력이 이미 `.inp` 면 HyperMesh 를 건너뛰고 복사만 합니다.
2. CAD 면 `mesh/hm_wrapper.tcl` 을 만듭니다. 내용은 파라미터 몇 줄과 본 스크립트 `source` 입니다.
   ```tcl
   set ::YL(BATCH) 1
   set ::YL(INPUT) "C:/YL_AUTO/models/bushing.stp"
   set ::YL(OUT_DIR) "C:/YL_AUTO/auto_out/bushing_Ep2p0/mesh"
   set ::YL(ELEM_SIZE) 2.0
   set ::YL(ELEM_TYPE) "C3D10H"
   source "C:/YL_AUTO/hypermesh/YL_V5_batch.tcl"
   ```
3. `hmbatch.exe -tcl hm_wrapper.tcl` 로 GUI 없이 실행합니다.
4. 끝나면 Tcl 이 써 둔 `hm_status.txt`(STATUS=OK/FAIL, N_TET, BAD_TRIA 등)를 읽어 성공 여부를 판단합니다.

### Tcl 쪽 (`YL_V5_batch.tcl`)
메시 알고리즘 자체(STEP 1~5 : 면 분류 Case A/B, Guide-Rail 노드 보존, F3 엔진, 품질 게이트 직선화, Aspect>5 제거 루프, Tetra 생성)는 연구실 YL_V4 코드를 그대로 썼습니다. 자동화를 위해 바꾼 곳은 아래 표와 같습니다.

| 표시 | 바뀐 내용 |
|---|---|
| [B1] | 입력창(`hm_getfloat`)과 선택 패널 대신 `::YL()` 파라미터 사용. 면은 불러온 전체를 자동 선택 |
| [B2] | STEP 0 추가 : `*geomimport` 로 CAD 자동 불러오기 (.hm 은 `*readfile`) |
| [B3] | Tetra 생성 후 `*feoutputwithdata` + `standard.3d` 템플릿으로 Abaqus INP 출력 |
| [B4] | 메시지 박스 대신 `hm_status.txt` 에 결과 기록 후 종료 |
| [B5] | STEP 1~5 를 오류 보호로 감쌈. 단계마다 `STAGE ...` 를 로그·상태 파일에 기록하고, Tcl 오류가 나거나 Tetra 가 0개면 단순 메시(전체 면 Tria → Tetra)로 한 번 더 시도. config `hypermesh.fallback_simple: false` 면 끔 |
| [B6] | 배치 확인창 대응. `*replacenodes`·`*equivalence`·`*deletemark` 같은 명령은 GUI 에서 "요소가 없어집니다, 계속할까요?" 확인창을 띄우는데, hmbatch 에서는 이게 `Invalid interactive routine called while in batch mode` FatalError 로 프로그램이 즉사함(catch 로도 못 잡음). 그래서 이런 명령은 전부 `yl_hm` 으로 감싸 실행 직전에 `hm_answernext yes`(GUI 에서 '예' 누른 것과 같음)를 건다. 그래도 HyperMesh 가 죽으면 `runners.py` 가 hmbatch 를 새로 띄워 `::YL(SKIP_V4)=1`(YL_V4 건너뛰고 단순 메시)로 자동 재시도. 1차 로그는 `*_try1.*` 로 남김 |

> 새 HyperMesh 명령을 YL_V4 에 추가할 때 규칙: 노드·요소를 지우거나 합치거나 옮기는 명령은 반드시 `yl_hm *명령 ...` 형태로 쓸 것. 그냥 쓰면 GUI 에서는 잘 되다가 배치에서만 죽습니다.

`::YL` 값이 없으면(GUI 에서 직접 source 하면) 예전 V4 처럼 입력창과 패널로 동작합니다. 그래서 메시 알고리즘을 개선할 때는 GUI 에서 먼저 테스트하고 같은 파일을 배치에 그대로 쓰면 됩니다.

확인할 파일: `mesh/hm_log.txt`(진행 로그), `mesh/hm_console.log`(hmbatch 화면 출력), `mesh/hm_status.txt`

## 5. [2] build 단계 : 메시 보정 + 세트 + INP 쓰기

관련 코드: `stage_build()`, `core/inp_mesh.py`, `core/inp_writer.py`

HyperMesh 가 뽑은 INP 에서 **메시(절점, 요소)만** 읽고, 나머지 모델 정의는 전부 Python 이 새로 씁니다. 그래서 HyperMesh 쪽에서 세트나 재료를 잡을 필요가 없습니다.

### 5-1. 메시 읽기와 보정 (`inp_mesh.py`)
순서대로 실행됩니다.

| 함수 | 하는 일 |
|---|---|
| `read_inp_mesh()` | `*Node`, `*Element` 읽기. `*Include` 도 따라감. 요소 종류(tet4/tet10/hex8) 판별 |
| `upgrade_tet4_to_tet10()` | HyperMesh 에서 2차 변환이 안 되어 Tet4 로 나오면 모서리 중점에 절점을 추가해 Tet10 으로 바꿈 |
| `fix_tet10_midside_order()` | 중간절점 5~10번이 Abaqus 규칙(1-2, 2-3, 3-1, 1-4, 2-4, 3-4 모서리)과 맞는지 검사하고, 다르면 재배열 |
| `fix_orientation()` | 체적이 음수인 요소(절점 순서가 뒤집힌 요소)를 찾아 순서를 바꿈 |
| `tet_quality()` | 형상 품질(정사면체=1), 최소 체적, 중간절점 이탈률 계산 → `model_info.json` |

### 5-2. 축을 +Y 로 세우기 (`align_axis_to_y`)
- 요구조건이 "축은 무조건 Y, 반경 방향은 XZ 평면"이라서, 어떤 방향으로 그린 CAD 든 회전시켜 맞춥니다.
- `axis: "auto"` 면 `detect_axis()` 가 판단합니다. 바운딩박스 중심을 지나는 X/Y/Z 직선 중 재료와 가장 멀리 떨어진 직선(= 구멍이 뚫린 방향)을 축으로 봅니다.
- 회전행렬은 3개뿐입니다(`ROT_TO_Y`). X→Y 는 Z축 +90°, Z→Y 는 X축 −90° 회전이고, 행렬식이 +1 이라 요소 방향이 뒤집히지 않습니다.
- `center: "none"` 이 기본이라 원점은 옮기지 않습니다. CAD 원점이 보어 중심이 아니면 `center: "bbox"` 로 바꿔야 합니다(아래 경고 참고).

### 5-3. INNER / OUTER 자동 선택 (`classify_inner_outer`)
연구실 방식대로 안쪽 코어 접착면 = INNER, 바깥 외통 접착면 = OUTER 로 잡습니다.

1. `boundary_faces()` : 모든 요소 면 중 한 번만 나오는 면 = 바깥 표면입니다. 면마다 바깥쪽 법선, 중심, 면적을 구합니다.
2. 면 중심의 반경 \( r = \sqrt{x^2 + z^2} \) 과 반경 방향 단위벡터 \( e_r \) 를 구하고, 법선과의 내적 \( n \cdot e_r \) 을 계산합니다.
   - \( n \cdot e_r < -0.6 \) : 축 쪽을 보는 면 (안쪽 후보)
   - \( n \cdot e_r > +0.6 \) : 바깥을 보는 면 (바깥 후보)
   - 0.6 은 `normal_cos_min` (각도로 약 53°)
3. **OUTER** : 바깥 후보 중 반경이 가장 큰 띠 (\( r \ge r_{max} - 0.5 \) mm, `outer_tol_mm`)
4. **INNER** : 안쪽 후보 중 반경이 가장 작은 띠 (\( r \le r_{min} + 0.5 \) mm)에서 시작해, 이웃한 안쪽 면을 계속 따라가며 포함합니다(`inner_mode: "connected"`). 그래서 보어가 원형이 아니어도(각진 코어, 키 홈) 전체 접착면이 잡힙니다. 공극(void) 벽면은 보어와 이어져 있지 않아서 들어가지 않습니다.
5. 두 세트에 동시에 들어간 절점이 있으면 에러로 멈춥니다(허용오차를 줄여야 함).
6. INNER 절점으로 원을 최소자승 피팅해 보어 중심을 구하고, 원점에서 0.1 mm 이상 떨어져 있으면 경고를 냅니다. LOAD_RP 가 (0,0,0) 이라서 중심이 어긋나면 결과가 틀어지기 때문입니다.

자동 선택이 틀리면 config 의 `models` 항목에서 모델별로 `inner_r_max`, `outer_r_min`, `inner_tol_mm` 등을 직접 줍니다. 결과는 반드시 `<tag>_SETS.png` 그림으로 확인합니다.

### 5-4. 메시 전용 INP (`write_mesh_inp`)
`run/<tag>_mesh.inp` 하나에 메시만 들어 있고, 모든 Job 이 이 파일을 `*Include` 합니다.
```
*Node                       ← 회전이 끝난 좌표
*Node, nset=LOAD_RP         ← 마지막 절점번호+1, (0, 0, 0)
*Element, type=C3D10H, elset=RUBBER
*Nset, nset=INNER
*Nset, nset=OUTER
*Nset, nset=rp / rp_node / sw   ← 연구실 기존 실행기와 같은 세트 이름 (별칭)
```

### 5-5. Job INP (`write_job_inp`)
Job 하나 = 스웨징 값 하나 × 하중 방향 하나입니다. 실제로 만들어지는 파일의 뼈대는 이렇습니다.
```
*Include, input=bushing_Ep2p0_mesh.inp
*Rigid Body, ref node=LOAD_RP, tie nset=INNER     ← 안쪽 코어 = 강체, LOAD_RP 로 움직임
*Solid Section, elset=RUBBER, material=FJ5045
*Material, name=FJ5045
*Hyperelastic, ogden, n=3
mu1, a1, mu2, a2, mu3, a3, D1, D2
D3
** Step-1 : 스웨징
*Step, name=Step-1_SWAGE, NLGEOM=YES, inc=2000
*Static
0.1, 1, 1e-08, 0.25
*Boundary
LOAD_RP, 1, 6, 0.                ← 스웨징 중에는 코어 고정
OUTER 절점마다 ux, 0, uz          ← 반경 방향 강제변위 (SW=0 이면 OUTER 1~3 고정)
** Step-2 : 정특성 하중
*Step, name=Step-2_X_PLUS, NLGEOM=YES, inc=2000
*Static
0.02, 1, 1e-08, 0.05
*Boundary
LOAD_RP, 1, 1, 2                 ← X 방향 2 mm 변위 제어
```
- 스웨징 변위는 OUTER 절점마다 \( u_x = SW \cdot x/r,\ u_z = SW \cdot z/r,\ u_y = 0 \) 입니다. 즉 XZ 평면에서 반경 방향으로만 밀거나 당깁니다.
- 부호 규칙: `swaging_outward_positive: true` 이면 **+ 가 바깥쪽(반경 증가), − 가 안쪽(압축)** 입니다. 실제 외통 스웨징(지름 축소)은 − 쪽에 해당하니 결과를 볼 때 헷갈리지 않게 주의하세요. 연구실 기존 정의와 다르면 이 값을 false 로 바꾸면 됩니다.
- Step-2 의 OUTER 는 Step-1 경계조건이 그대로 이어져 스웨징 위치에 고정된 상태입니다.
- 출력: LOAD_RP 의 U1~U3, RF1~RF3 를 매 증분 history 로 저장합니다. 필드 출력(U, RF, S, LE)은 5 증분마다입니다.
- 안쪽 구속은 기본이 `*Rigid Body`(연구실 `modeling_AN_M1.inp` 와 같은 방식)이고, `inner_constraint: "coupling"` 으로 바꾸면 `*Coupling + *Kinematic` 을 씁니다.
- Job 이름 규칙(`job_name`): `<모델>_E<메시크기>_SW<스웨징>_<방향><부호>`. 숫자의 점은 p, 음수는 m 입니다.
  예) `bushing_Ep2p0_SWm1p0_XP` = 메시 2.0 mm, 스웨징 −1.0 mm, X+ 방향

## 6. [3] run / [4] extract 단계

관련 코드: `stage_run_one()`, `runners.run_abaqus()`, `runners.abaqus_status()`, `runners.extract_odb()`, `abaqus_scripts/extract_odb.py`

### 해석 실행
`run/` 폴더 안에서 아래 명령을 실행합니다.
```
abaqus job=<job> input=<job>.inp cpus=4 interactive ask_delete=OFF
```
- `interactive` 라서 해석이 끝날 때까지 기다린 다음 다음 Job 으로 넘어갑니다.
- 끝나면 `.sta` 파일에서 "THE ANALYSIS HAS COMPLETED SUCCESSFULLY" 와 증분 수를, `.msg`/`.dat` 에서 `***ERROR` 를 읽어 `<job>_status.json` 에 저장합니다.
- `timeout_min`(기본 180분)을 넘으면 `abaqus terminate` 로 멈춥니다.
- 이미 성공한 Job 은 다시 돌리지 않습니다. 다시 돌리려면 `--force`.

### ODB 에서 결과 꺼내기
```
abaqus python extract_odb.py <job>.odb <job>_RP.csv <LOAD_RP 절점번호>
```
- Abaqus 안의 Python 으로 실행됩니다(2021 은 Python 2.7). 그래서 이 파일에는 f-string 같은 Python 3 문법을 쓰면 안 됩니다.
- 1순위로 history output(`Node xxx.<RP번호>`)을 읽고, 없으면 field output 의 LOAD_RP 세트를 읽습니다.
- CSV 열: `step, step_time, total_time, U1, U2, U3, RF1, RF2, RF3`

## 7. [5] report 단계 : 강성 계산과 자동 QC

관련 코드: `stage_report()`, `core/results.py`

### 하중-변위 곡선 만들기 (`analyze_job`)
- CSV 에서 등장 순서로 Step-1(스웨징)과 Step-2(하중)를 나눕니다.
- 스웨징이 끝난 시점의 값을 0 으로 빼서 Step-2 만의 순수한 \( u, F \) 를 만듭니다. 스웨징 후 남은 반력은 `swage_RF_end` 로 따로 저장합니다(예하중).
- 하중 방향으로 부호를 맞춰 양수로 만듭니다.

### 강성 정의
| 항목 | 정의 |
|---|---|
| `K_secant` | \( F_{end} / u_{end} \) (최대 변위까지의 할선 강성) |
| `K_initial` | 진폭 10% 이하 구간 직선 피팅 기울기 |
| `K_sec_25/50/75` | 진폭 25/50/75% 지점의 할선 강성 |
| `K_tangent_end` | 마지막 3~4점 직선 기울기 |

### 자동 QC
| 항목 | 기준 |
|---|---|
| `completed_full_step` | Step-2 시간이 1.0 까지 갔는지 (중간에 발산하면 FAIL) |
| `reached_amplitude` | 목표 변위(2 mm)에 도달했는지 |
| `enough_points` | 곡선 점이 6개 이상인지 |
| `monotonic_force` | 하중이 중간에 줄어들지 않는지 |
| `positive_stiffness` | 강성이 양수인지 |

모델 단위로는 `model_level_checks()` 가 스웨징마다 Kx/Kz 비(축대칭이면 1 에 가까워야 함, 허용 10%)를 확인하고, 방향별로 스웨징에 따른 K_secant 변화를 나열합니다.

## 8. 물성 (`core/ogden.py`)

Abaqus 의 Ogden 정의를 그대로 씁니다.
\[
W = \sum_{i=1}^{3} \frac{2\mu_i}{\alpha_i^2}\left(\bar\lambda_1^{\alpha_i}+\bar\lambda_2^{\alpha_i}+\bar\lambda_3^{\alpha_i}-3\right) + \sum_{i=1}^{3}\frac{1}{D_i}(J-1)^{2i}
\]
- 초기 전단계수 \( \mu_0 = \sum \mu_i \), 초기 체적계수 \( K_0 = 2/D_1 \)
- FJ5045 는 `modeling_AN_M1.inp` 의 계수를 그대로 넣었습니다 (μ0 ≈ 0.759 MPa).

물성을 넣는 방법은 두 가지입니다.
1. **계수를 아는 경우** : config 에 `ogden3: {mu: [...], alpha: [...]}` 와 `D` 를 적습니다.
2. **시험데이터만 있는 경우** : `test_data` 에 단축(uniaxial)/등이축(biaxial)/평면(planar) CSV(공칭변형률, 공칭응력 MPa)를 적으면 `fit_ogden3()` 가 피팅합니다.
   - 시작점 300개로 짧게 탐색 → 상위 8개만 정밀 수렴하는 방식이라 국소해에 덜 빠집니다.
   - 오차는 상대오차로 계산해서 작은 변형률 구간도 무시되지 않습니다.
   - \( \mu_i \alpha_i > 0 \) 을 강제하고, 신장비 0.2~5.0 구간에서 Drucker 안정성이 깨지면 벌점을 줍니다. 해석이 발산하지 않게 하려는 장치입니다.
   - 결과의 R², 모드별 상대오차가 `materials_ogden3.json` 의 `fit_report` 에 남습니다.

## 9. 코드를 고칠 때 어디를 보나

| 하고 싶은 것 | 고칠 곳 |
|---|---|
| 스웨징 값, 하중 방향, 변위 크기 | config `swaging_mm`, `load.directions`, `load.amplitude_mm` (코드 수정 불필요) |
| 음(−) 방향 하중도 | config `load.signs: [1, -1]` |
| 메시 크기 여러 개 비교 | config `mesh.elem_sizes: [1.5, 2.0, 3.0]` |
| 수렴이 안 될 때 증분 | config `steps.load_inc` (초기, 전체, 최소, 최대) |
| INNER/OUTER 가 틀릴 때 | config `models` 에 모델별 `inner_r_max`, `outer_r_min`, `axis`, `center` |
| 메시 알고리즘 자체 | `hypermesh/YL_V5_batch.tcl` (STEP 1~5 구간) |
| INP 에 키워드 추가 (예: 접촉, 출력 변수) | `core/inp_writer.py` 의 `write_job_inp()` |
| ODB 에서 다른 값 꺼내기 | `abaqus_scripts/extract_odb.py` (Python 2.7 문법 유지) |
| 강성 정의나 QC 기준 | `core/results.py` 의 `analyze_job()` |
| 학습용 열 추가 | `inp_mesh.geometry_features()` 또는 `stage_report()` 의 `row` |

고친 다음에는 바로 전체를 돌리지 말고 `python run_pipeline.py config_abaqus.json --stage mesh,build` 로 INP 까지만 만들어 Abaqus/CAE 에서 열어 확인하는 습관을 들이면 좋습니다.
