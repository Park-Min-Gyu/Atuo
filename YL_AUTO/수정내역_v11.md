# YL_AUTO v11 수정 내역 (2026-11-13, ODB 를 모델당 1개로)

## 바뀐 점
- 예전 : 스웨징 5개(-2,-1,0,1,2) x 하중방향 3개 = Job 15개, ODB 15개
- 지금 : **모델당 Job 1개, ODB 1개** (`<모델>_E..._ALL.odb`) 안에 15개 케이스가 스텝으로 모두 들어감

`config_abaqus.json` 의 `"odb_mode": "single"` 이 새 방식. `"separate"` 로 바꾸면 예전처럼 Job 마다 ODB 1개.

## ODB 안의 스텝 구성 (스웨징 오름차순, 총 35 스텝)
```
SWm2p0_SWAGE                 스웨징 -2 mm
SWm2p0_XP_LOAD / _BACK       X 하중 -> 0 으로 원위치
SWm2p0_YP_LOAD / _BACK
SWm2p0_ZP_LOAD / _BACK
SWm1p0_SWAGE                 스웨징 -1 mm  (이하 같은 순서로 0, +1, +2)
...
```
- 고무(Ogden 초탄성)는 이력에 의존하지 않으므로, 하중을 0 으로 되돌린 뒤 다음 하중을 걸면 따로 돌린 것과 같은 곡선이 나온다.
- `_BACK`(원위치) 스텝은 마지막 프레임만 저장해서 용량을 줄였다.
- 메시·재료가 ODB 에 한 번만 저장되고 .dat/.msg/.sta 등도 15벌 -> 1벌.

## 결과 파일은 예전과 같다
ODB 1개에서 LOAD_RP 곡선을 뽑아 `<job>_RP.csv` 15개로 다시 나누므로
`dataset/summary.csv`, `curves.csv`, `qc_report.md`, 그래프는 예전 형식 그대로 15줄이 나온다.

## 알아둘 점
- Job 1개가 15 케이스를 차례로 계산하므로 **중간 스텝이 발산하면 그 뒤 케이스는 계산되지 않는다.**
  그 전까지 끝난 케이스는 ODB 에서 그대로 추출되고, 로그에 `하중 케이스 9/15 개 완료` 처럼 표시된다.
- 시간 제한(`abaqus.timeout_min`)은 케이스 수만큼 자동으로 곱해진다.
- 용량을 더 줄이려면 `steps.field_freq` (기본 5 = 5 증분마다 저장)를 10~20 으로 올린다.
- 예전 방식으로 만든 `run` 폴더의 ODB 15개는 자동으로 지우지 않는다. 필요 없으면 직접 삭제.

## 검증 범위
Abaqus 가 없는 환경이라 **실제 해석은 돌려 보지 못했다.** INP 생성, 실행/추출/15개 분리/리포트 흐름,
중간 발산 시 부분 추출은 가짜 Abaqus 명령으로 확인했다. 첫 실행 때 `SWm2p0_XP_LOAD` 강성이
예전 `..._SWm2p0_XP` 결과와 같은지 한 번 비교해 보는 것을 권한다.

## 실행 (메시는 재사용, INP 부터 다시 만듦)
```
run_all.bat --stage build,run,extract,report
```
